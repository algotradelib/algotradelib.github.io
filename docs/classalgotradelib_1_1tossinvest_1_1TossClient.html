Detailed Description

The asynchronous Toss Securities REST client: market data, accounts and orders.

It requests an access token when first needed, and again after Toss refuses the one it holds (as it does once another program issues a token with the same key); one refresh is shared among concurrent requests, and a refused request is not sent again. Create it with std::make_shared. Each completion runs on the handler's associated executor, or on the client's strand if it has none. A blocking wrapper is TossBlockingClient.

auto algotradelib::tossinvest::TossClient::async_place_order ( std::int64_t account_sequence,
OrderRequest order,
CompletionToken && token )
inline

Places an order.

The request is never resent. After an error for which runner::outcome_of returns INDETERMINATE (BrokerError::reached_broker_ set and a category of TRANSPORT, CANCELLED or PROTOCOL, or HTTP with a status of 500 or more), the outcome is unknown. Toss's refusals other than a rate limit are reported as PROTOCOL, so they count too. With OrderRequest::client_order_id_ set, Toss treats it as an idempotency key for ten minutes, so sending the same order again returns the original result; without one, read async_orders before placing again.

Refused before sending, among others: an instrument whose venue is not Toss's own (COMBINED for Korea, UNSPECIFIED for the US); an OrderRequest::venue_; a trigger price; a type other than limit or market; a condition other than DAY; an unsupported session; a fractional quantity (except a US market sell, up to six decimals); a Korean price that is not whole won; a client order id that is not 1-36 characters of [A-Za-z0-9_-].

Amends an open order's price, and for a Korean order its quantity.

After an error of unknown outcome (see async_place_order) the amendment may have been made; an amendment has no idempotency key. Toss answers with a new id in OrderAck::order_id_, naming this amendment. If Toss carries it out, the original becomes REPLACED and the order rests under the new id; if Toss rejects it, the new id names a REPLACE_REJECTED row and the original rests unchanged under its own id. Read the order's state before acting on either id.
