Detailed Description

The asynchronous Kiwoom REST client: market data, account inquiries and orders for domestic stocks.

It requests an access token when first needed and shares one refresh among concurrent requests. Create it with std::make_shared. Each completion runs on the handler's associated executor, or on the client's strand if it has none. Before trading, state the holdings settings in KiwoomConfig. A blocking wrapper is KiwoomBlockingClient.

Requests bars, following Kiwoom's continuation pages from before_'s Korean date (or today).

before_ applies by day only: minute bars later than it on the same date are returned. A short series comes back only when Kiwoom has no more. next_cursor_ is set when the series is full and Kiwoom said there is more, and never for minute bars. If Kiwoom offers more but its continuation key is blank, a page adds nothing, or 50 pages were read, the request fails (PROTOCOL, incomplete_listing) instead of returning a partial series. Refused before sending: count_ of zero or less, or a symbol that is not Korean or malformed.

Cancels an order, all or part of it (kt10003).

After an error of unknown outcome (see async_place_order) the order may still rest. Refused before sending, among others: a cancellation without a venue, an order number or a symbol; a fractional or negative quantity; or one carrying a price or trigger price.

Two refusals are recognized as refusals, each from its own server only: the demo server's RC4033 (nothing left to amend or cancel) and the real server's 506550 (no quantity left to cancel) are INVALID_ARGUMENT with reached_broker_ set (kiwoom_recognized_refusal). Each says the cancellation did nothing, not what became of the order: it may have filled. Either code from the other server stays PROTOCOL.

OrderRequest order,
CompletionToken && token )

Places an order (kt10000 buy, kt10001 sell).

The request is never resent. After an error for which runner::outcome_of returns INDETERMINATE (BrokerError::reached_broker_ set and a category of TRANSPORT, CANCELLED or PROTOCOL, or HTTP with a status of 500 or more), the order may exist. That includes a reply without an order number and an unrecognized failure code Kiwoom declares but does not document (both PROTOCOL). Read async_open_orders or async_order_history before placing again, since Kiwoom has no idempotency key.

Some refusals are recognized as refusals, each from its own server only: the demo server's 800033 (not enough to sell), RC4057 (the market has not opened) and RC4058 (the market has closed), and the real server's 571445 (no securities balance), are INVALID_ARGUMENT with reached_broker_ set, which runner::outcome_of reads as REJECTED (kiwoom_recognized_refusal). A demo code from the real server, or the real code from the demo server, stays PROTOCOL, as does every other refusal this client does not classify further (its documented error codes keep their categories).

Refused before sending, among others: an instrument that is not Korean or whose venue_ is not COMBINED (route with OrderRequest::venue_); no venue on the order; a client order id; a quantity that is not a positive whole number; a missing, non-positive or fractional price on a priced type, or a price on an unpriced one; a trigger price missing or invalid on STOP_LIMIT, or present on another type; a shape Kiwoom has no code for; and any order while KiwoomConfig::holdings_position_scope_ is not stated.
