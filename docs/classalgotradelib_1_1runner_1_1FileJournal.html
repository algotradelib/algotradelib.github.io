Detailed Description

The order journal on disk: one JSON object per line, appended and flushed to disk (fsync) before append returns.

A write cut short loses only the last line, which shows as missing its newline. Read it with tail. The file starts with a header naming its broker and account; opening a file that belongs to another account is refused.

On POSIX, opening takes an exclusive flock on the file, so a second journal on the same file (in any process) is refused and a program built on it starts nothing. The lock is on the open file, not the path: deleting or renaming the file while it is open lets another journal create and lock a new file at the same path, so do not rotate an active journal. It ends when the process exits, unless a forked child still holds the descriptor (it is closed on exec, not on fork). Keep the journal on a local disk (flock and fsync over NFS are unreliable). Windows takes no lock. A flushed line survives a killed process everywhere; on macOS fsync does not guarantee it survives a power loss. Two journals at different paths for one account are not detected.
