Detailed Description

What a strategy is, how a runner calls its handlers, and ATL_ASSERT_STRATEGY.

A strategy is a plain struct whose handlers are member templates on the context type. Every handler is optional; declare only the ones you need:

struct MyStrategy {
struct Params { std::size_t window_{20}; };
Params params_;
template <class Ctx> void on_start(Ctx& ctx);
template <class Ctx> void on_bar(Ctx& ctx, const BarEvent& bar);
template <class Ctx> void on_quote(Ctx& ctx, const QuoteEvent& quote);
template <class Ctx> void on_fill(Ctx& ctx, const Fill& fill);
template <class Ctx> void on_order_update(Ctx& ctx, const OrderSnapshot& order);
template <class Ctx> void on_phase(Ctx& ctx, const MarketPhase& phase);
template <class Ctx> void on_stop(Ctx& ctx);
};

Because the handlers are templates, the same strategy runs under every runner: a dry run, a live session with any broker, and a backtest. Take the context by reference; a context cannot be copied, so a handler that takes it by value does not compile.

Warning
on_fill is called in a backtest but never by the shipped live loop; see Fill.

Asserts at compile time that S is a strategy a runner with context Ctx can drive.

Checks that:

  • S is a class and not final;
  • Ctx cannot be copied, so a handler taking it by value does not compile;
  • S declares at least one handler;
  • every handler S declares can be called the way a runner calls it with Ctx. Each handler's body is compiled for Ctx, including handlers for events the program never feeds.

With MinimalContext or FullContext it checks handlers against a probe without series accessors; a strategy that reads bars() is checked by its runner instead. Usable at namespace, class and block scope.

Parameters
SThe strategy type.
CtxThe context type.
Note
Not detected: a handler that takes by value a copyable base class of the context.

Detects that S declares a member named NAME: of any kind, signature or access, inherited included.

Handlers are optional, so something has to decide whether to call one, and this is it: a declared name is called, and a call that does not compile is the compiler's error at the call (see dispatch). The name is what the author wrote; asking instead whether a particular call compiles would read a handler with a wrong parameter as absent and skip it in silence. Looking NAME up in a class that derives from S and from one declaring int NAME is ambiguous exactly when S declares it, which works for a member template, where &S::NAME cannot name one.

A final class cannot be derived from, and a non-class type has no members, so neither can be looked into; dispatch and StrategyConformance refuse both rather than read them as declaring nothing.
