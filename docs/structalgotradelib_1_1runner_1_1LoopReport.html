Detailed Description

What a whole PollingLoop::run did, and why it ended.

Read notes_ first; they explain anything the run could not do. Scope of the counters: the orders_*, cancels_*, plans_withheld_ and instructions_unavailable_ outcomes (and last_broker_refusal_, last_unbuildable_) cover the run's polling, before any closing pass, whose results are the closing_* fields; price_bands_withheld_, unclamped_orders_* and sends_outside_permitted_phase_ cover the whole run, closing pass included.

◆ closing_complete()

bool algotradelib::runner::LoopReport::closing_complete ( ) const
inlinenoexcept

Tests whether every closing instruction the loop asked for was accepted, and the loop knew what to ask for.

Meaningful only after a WITHDRAW or FLATTEN stop (stopped_by_): a run that ended otherwise, or with QUIESCE, also returns true, having checked nothing. true does not mean flat or nothing resting: an accepted closing order may not have filled, and an accepted cancellation may not have completed. Read the broker's order list and holdings for the state.

Returns
false if any closing instruction was rejected, refused, withheld, of unknown outcome, unavailable or unresolved, or any position was contended or unsizable, or the source was unverified, or an order nothing explained was still owed.

◆ closing_contended_

std::size_t algotradelib::runner::LoopReport::closing_contended_ {0}

Positions whose closing order was sized down, or not sent, because another order could close them too.

A flatten cancels every listed order and then closes the position, but a same-side order can fill while its cancellation is pending. So the close is sized to the holding minus what is working on that side, or not sent at all when the listing cannot be trusted (closing_source_unverified_). Makes closing_complete() false.

◆ closing_source_unverified_

bool algotradelib::runner::LoopReport::closing_source_unverified_ {false}

Whether the closing pass could not trust its picture of the account. Makes closing_complete() false.

Set if the order list was never read, the source publishes no working orders, no working-order listing was read or it is older than the portfolio age limit, an order was placed (or sent with an unknown outcome) after that listing, holdings were never read or are too old, or the listing is newer than the holdings. Then a FLATTEN places no closing orders at all, while the withdrawals of the orders it knows of are still sent.

A verified source still lists only what the broker's listing shows: at Toss, an order of a type the API does not list (such as an after-hours closing-price order placed in the app) is in no listing, so a flatten can neither withdraw it nor size around it.
