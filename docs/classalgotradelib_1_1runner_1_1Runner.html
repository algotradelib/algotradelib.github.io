Detailed Description

template<typename Strategy, typename CapsType = strategy::NoCaps, typename BrokerTag = DryTag, typename Executor = RecordingExecutor<DryTag>>
class algotradelib::runner::Runner< Strategy, CapsType, BrokerTag, Executor >

Runs one strategy: feeds it events, reconciles what it asks for, checks the risk limits, and sends through an executor.

The same class serves a dry run (the default RecordingExecutor, which sends nothing), a live session (live::SessionExecutor) and a backtest (backtest::QueueingExecutor). Feed events with feed; each call runs the matching handler and returns a DryRunReport of what it decided. A live program usually drives it through runner::PollingLoop.

A dry-run program contains no broker or network code: this header includes none.

inline

Lets several orders on one instrument be outstanding at once, as an unjournaled runner does, with that runner's known limitations.

After a restart, orders a previous process sent and holdings had not yet shown are forgotten, and a target can place them again. A buy and a sell on one instrument whose fills have not reached holdings can both be taken as accounted for, and a later order confirmed by another's fill. Choose it only for a strategy that needs overlapping orders (an entry beside its protective stop) and accepts those.

Settles reserved orders against the broker's order history; sends nothing.

A terminal row for an order caps the quantity holdings must still show at its filled quantity; an order that ended with nothing filled is forgotten at once. After the runner has seen the phase CLOSED or POST_CLOSE since the order was sent, an open row of a DAY order counts as terminal (its filled quantity is final); not for a serialized runner, whose rules are under serialized. An order the history settled, or had no answer for after the timeout, withholds its instrument (orders_unconfirmed_timed_out) if a holdings read a timeout later still does not show it; see set_confirmation_timeout.

std::vector< strategy::TargetPosition > algotradelib::runner::Runner< Strategy, CapsType, BrokerTag, Executor >::deferred_targets ( ) const

Returns the targets waiting for a stop on their instrument to be cancelled (at most one per instrument).

A target that needs a trade while a stop rests cancels the stop and waits (strategy::RejectReason::STOP_ORDER_RESTING); the runner keeps it so it is not lost when no strategy callback follows. It is:

  • replaced by any later target or order intent the strategy states for the instrument;
  • released (and settled) by retry_deferred once each stop it waits on is no longer listed and its history row is terminal with nothing filled;
  • dropped without sending if a stop shows any fill (counted in deferred_dropped_after_fill; a partial fill's remainder is left for the strategy to restate);
  • kept while a stop is still listed or its history is missing or not terminal.

Not journalled: a restart loses it.

Returns
The waiting targets.
