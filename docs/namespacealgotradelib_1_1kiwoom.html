◆ kiwoom_recognized_refusal()

std::optional< BrokerError > algotradelib::kiwoom::kiwoom_recognized_refusal ( int http_status,
const boost::json::object & document,
KiwoomOrderOperation operation,
bool demo )
inline

Reads the refusal a cash-order reply states, for the replies this client recognizes as one.

From the demo server: a placement answered 800033 (not enough to sell), RC4057 (the market has not opened) or RC4058 (the market has closed), and a cancellation answered RC4033 (nothing left to amend or cancel). From the real server: a placement answered 571445 (no securities balance) and a cancellation answered 506550 (no quantity left to cancel). Such a reply is INVALID_ARGUMENT with reached_broker_ set, which a runner reads as a rejection; any other reply with return_code 20 stays PROTOCOL, an unknown outcome.

Each code is recognized from the server it was seen from only: a demo code from the real server, or a real code from the demo server, is not. The reply must be HTTP 200 with return_code 20 (a JSON integer, or the string "20"), a return_msg of the shape kiwoom_refusal_code reads, and none of what an acknowledgement carries: ord_no absent or empty, and cncl_qty and mdfy_qty absent, empty or all zeros. A reply acknowledging a new order is never read as a refusal (the original order's number, echoed in base_orig_ord_no, is not an acknowledgement). A refused cancellation says only that the cancellation did nothing, not what became of the order it named.

Parameters
http_statusThe reply's HTTP status.
documentThe reply body.
operationThe instruction the reply answers.
demoWhether the request went to the demo server.
Returns
The error (broker_code_ the inner code, message_ Kiwoom's return_msg followed by the outer code and the rule that matched), or std::nullopt if the reply is not one of them.

◆ unestablished_holdings_scope()

std::optional< BrokerError > algotradelib::kiwoom::unestablished_holdings_scope ( )
inline

Makes the error that refuses a new order or an amendment while KiwoomConfig::holdings_position_scope_ is not stated.

Without it the library cannot establish what the account holds, so an order could be sized against an empty portfolio. An amendment is refused too, since repricing can make a resting order fill. Cancellations, including cancel_quantity(), are never refused. The client applies it to every placement and amendment, however they arrive.

Returns
An INVALID_ARGUMENT error (holdings_scope_unestablished, not sent) naming the setting.
