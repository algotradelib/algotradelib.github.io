Detailed Description

template<typename Broker>
struct algotradelib::strategy::Portfolio< Broker >

What the account holds and which orders are still working, as a strategy sees it.

Read it with ctx.portfolio(). Size orders against positions and working orders (net_quantity_of, working_quantity), or emit a TargetPosition and let the runner do it; sizing from positions alone buys twice after a partial fill.

Template Parameters
BrokerThe broker tag of the working orders' references; read the portfolio with auto so a strategy never names it.

◆ listing_newer_than_holdings()

template<typename Broker>
bool algotradelib::strategy::Portfolio< Broker >::listing_newer_than_holdings ( ) const
inlinenoexcept

Tests whether the working-order listing is newer than the holdings.

Then a resting buy that filled between the two reads appears in neither, and the portfolio under-counts the position. The runner withholds a plan sized against such a portfolio (WithheldPlanReason::PORTFOLIO_SUPERSEDED).

Returns
true if both are stamped and the listing arrived after the holdings.

Returns the sellable quantity the broker reported for an instrument (first row).

Sellable can be less than held (unsettled, pledged or locked shares). A broker that does not publish it leaves this absent; do not substitute the held quantity. To check a sell, prefer sellable_reading_for, which also says what the figure covers.

Returns an instrument's sellable quantity and its basis, taken from the same row.

A row's own basis is used if it has one, otherwise the portfolio's sellable_basis_. When an instrument has several rows, figures are not summed; if the rows' bases differ, or their figures differ under the same basis, the reading's basis is unestablished and RiskGuard refuses a checked sell.
