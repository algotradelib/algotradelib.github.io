Detailed Description

template<typename Client>
struct algotradelib::BrokerCaps< Client >

What one broker client implements, as compile-time constants.

Gate broker-specific code with if constexpr on these, so one strategy compiles against every broker. A traits specialization must answer every constant (none has a default); working_orders_state_terminal and sellable_inquiry_basis only where the inquiry they describe exists. ATL_ASSERT_BROKER reads them all.

A capability says the broker implements an operation, not that every account may call it: KIS does not offer its modifiable-order inquiry to demo accounts, so its adapter answers that read from the daily order inquiry there instead.

template<typename Client>
constexpr bool algotradelib::BrokerCaps< Client >::supports_interval ( BarInterval interval)
inlinestaticconstexpr

Tests whether the broker publishes bars of an interval.

KIS and Toss both publish minute and daily bars; only KIS publishes weekly, monthly and yearly. An interval a broker does not publish is refused, not aggregated from shorter bars.

Parameters
intervalThe interval.
Returns
true if the broker publishes it.

staticconstexpr

Whether the working-order listing can show a terminal status (filled, cancelled, ...).

false for KIS, Toss and Kiwoom: their listings show only open orders. Then an order that leaves the listing has no terminal on_order_update; read its outcome from holdings or an order inquiry instead of waiting for one. false here when has_working_orders is false.
