Binds a strategy to a broker session, so its instructions are sent to the broker.

This can place orders. bind_observer is the same pipeline with nowhere to send. The runner requires holdings to have been read before it places (see Runner::allow_absent_portfolio for a run that reads none).

Binds a strategy to a broker session, recording every instruction in a journal before it is sent.

Use this rather than building a runner::JournalingExecutor yourself: bind makes its own executor, so a journaling executor built beside it would never be used, and nothing would report it.

The runner is serialized (runner::Runner::serialized): one order per instrument until holdings account for it. Call runner::recover_runner with the journal before trading, on every start: it restores what a previous process left owed, and the runner places nothing until it has run. To keep several orders on one instrument outstanding instead, call allow_overlapping_orders first.

Binds a strategy for observation: the session's capabilities and broker tag, and nothing to send through.

A capability-gated strategy compiles the same branch as it would live. Nothing can be sent because the runner has no executor that reaches a broker; its reports list what would have been sent.
