Detailed Description

The production wiring of a live run, with no broker named: the part of example-live-program a consumer keeps.

example-live-program.cpp chooses a broker and calls live_program::trade or live_program::observe. Everything that makes a run safe to restart is here, in the order it has to happen, and the test suite drives it against an in-memory session – which a main could not be.

The order is the whole point, and each step exists because leaving it out fails silently:

  1. Open the journal before binding. A runner that cannot record what it sends should not send.
  2. Bind through the journal (live::bind_journaled). live::bind has no journal, so an order in flight when the process dies leaves no trace, and the next start may send it again.
  3. Recover before the loop starts (runner::recover_runner), so whatever a previous process left owed is withheld until the broker's own lists resolve it. The runner is serialized (Runner::serialized): it places nothing before recovery, and each order owns its instrument until holdings account for it, across restarts too.
  4. Let the source resolve the journal (SessionSource::set_journal). Without it every recovered instrument stays withheld forever.
  5. State every age the loop asks about. A run that states none holds; a run that says "unbounded" sizes against a portfolio nobody bounded.
  6. Stop by signal or by control file, and read closing_complete() at the end.
  7. Unattended, watch for orders that stay owed. A serialized order keeps its instrument until holdings or its own history account for it, and the indeterminacy ledger need not say so: an order counted as timed out (Runner::orders_unconfirmed_timed_out) marks it only if it was never named, and one whose history reads keep failing is not counted at all. The loop stops placing by itself for two kinds: an order no sweep has named yet (a later sweep may still find it) and one held for an operator, owed longer than Settings::owed_order_limit_ (Exit::OWED_ORDER). An order the broker named is not watched that way: watch how long each has been owed (Runner::obligations, its sent_at_) and a non-empty Runner::ledger. PollingLoop::run reports only when it returns and has no hook inside a run; calling it in short chunks is no substitute, since each call starts its failure budget and poll schedule afresh.

enum class live_program::Exit : int
strong

What the program exits with, so a supervisor can tell its endings apart.

Enumerator
CLEAN 0 

The run ended, and any closing pass it made got every instruction out.

CLOSING_INCOMPLETE 1 

A stop that closes ran and closing_complete() is false: read the broker's order list.

JOURNAL_REFUSED 2 

The journal would not open, so nothing was bound.

RECOVERY_HALTED 3 

Recovery halted the runner; nothing was started.

REFERENCE_UNREADABLE 4 

Reference data could not be read, so no order could be priced; nothing was started.

LOOP_ABANDONED 5 

The loop gave up after repeated poll failures: it was not trading when it returned.

LOCAL_FAILURE 6 

Local machinery failed during the run – usually a journal write – and the runner halted itself. Whatever it was sending when that happened is unknown until the broker's order list is read.

ACCOUNT_UNRESOLVED 7 

The program could not settle which account to trade (used by example-live-program).

OWED_ORDER 8 

The run stopped placing by itself: an order has been owed too long with nobody able to account for it. Starting again stops again; read the broker's lists and release the order first.

Runs a strategy against a session's account and another's market data, with nothing to send through.

live::bind_observer gives the runner the session's real capabilities and no executor that reaches the broker, so the pipeline, the guard and the gates all run, and no order can leave. No journal is opened.

Trades a strategy through a session, reading market data and reference data from another.

This places orders, through session only; market_data is only read. Use a session that cannot trade for market_data (a KIS session with an empty KisAccount, a Toss session with account sequence 0), so that a swapped pair refuses rather than trades.
