Detailed Description

template<typename Tag>
struct algotradelib::DataOnlyTraits< Tag >

A base for the BrokerTraits of a market-data client that cannot trade.

Inherit it and declare only what the vendor serves:

template <>
struct algotradelib::BrokerTraits<my::Client> : algotradelib::DataOnlyTraits<my::Tag> {
using Client = my::Client;
using Config = my::Config;
static constexpr std::string_view name = my::Tag::name;
static constexpr bool blocking = true;
static constexpr bool supports_interval(BarInterval interval);
static std::optional<BrokerError> validate_bars(const BarQuery& query);
static Result<QuoteSnapshot> quote(Client& client, InstrumentId instrument);
static Result<BarSeries> bars(Client& client, BarQuery query);
};
ATL_ASSERT_BROKER(my::Client); // in one source file

An asynchronous client takes the completion token as the last argument. To serve more (a calendar, reference data, price limits), declare that capability true and add its thunk.

Every account-side member (holdings, place, replace, cancel, history) refuses before any I/O with data_only::refusal(); none returns success, since an empty holdings or history would be read as facts about an account. So:

  • as a backtest source, or as the market-data session of a live::SessionSource, it is complete;
  • as the trading session of live::SessionExecutor or live::SessionSource (and so in live::bind and live::bind_journaled) it does not compile;
  • place or holdings called directly on its session fail at run time;
  • live_program::trade and observe (examples/live_program.hpp) also need reference data (has_reference_data).

The account-side members ignore their client, account, request, reference and instruction arguments, which are unnamed.

Note
A member you declare hides every inherited member of that name, overloads included (declaring a blocking holdings hides the asynchronous one); re-expose with using DataOnlyTraits<Tag>::holdings;.
Warning
Not a base for a trading adapter that is still incomplete.
