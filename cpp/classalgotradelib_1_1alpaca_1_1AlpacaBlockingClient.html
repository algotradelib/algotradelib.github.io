Detailed Description

A blocking client for Alpaca's Trading API and Market Data API: exchange-listed US equities, whole shares, limit and market day orders in the regular session.

Paper trading unless AlpacaConfig::is_demo_ is false; live is the same code path on another host. Each call runs its requests on a private event loop over two network::AsyncHttpClient connections (trading, market data) and returns the result. Not thread-safe: one session uses it.

When HttpClientOptions::rate_limit_ is empty, each connection is paced at one request a second with a burst of two, one of them reserved for orders (RateLimitBudget{2, 1, 1}), under Alpaca's 200 a minute even if both hosts share one allowance; a budget you set is used as given, on each connection.

Every placement is checked by detail::validate_order, then reads the asset (refusing OTC and anything not active and tradable), for a sell the position (refusing a sell above it), and Alpaca's clock (refusing unless the regular session is on), before the order is sent. A refusal for the clock is CANCELLED with reached_broker_ false, which a runner keeps and offers again; the others are not sent either.

Returns the New York Stock Exchange's trading calendar with each open day's session hours, as instants (/v3/calendar/XNYS).

Without from, it covers 41 days from the UTC date ten days before now, so the last trading day before now and the next ones after it are both listed; with from, 41 days from it. A listed date is open, with regular_ from its core session and extended_ from its pre-market start to its post-market end when both are stated; an unlisted date is closed. A date listed twice or outside the range fails the read.

Returns the US equity positions (/v2/positions), in dollars.

The sellable figure is qty_available, with the basis {WHOLE_HOLDING, DEDUCT, verified_ = false}. The read fails (PROTOCOL, invalid_holdings_response) when a symbol appears twice among all rows, when a row names no symbol or class, and when a us_equity row is short or has no readable qty: a short equity position anywhere in the account stops the read. Rows of other classes (crypto, options) are skipped.

◆ place_order()

Result< AlpacaOrderAck > algotradelib::alpaca::AlpacaBlockingClient::place_order ( AlpacaAccount account,
OrderRequest order )
inline

Places an order (POST /v2/orders). The outcome can be unknown after an error.

Before anything is sent, it refuses what detail::validate_order refuses; then it reads the asset (instrument_not_listed for OTC or an exchange not known to be national, instrument_not_tradable), for a sell the position (no_position, sell_exceeds_position above qty_available or qty), and last Alpaca's clock for the New York Stock Exchange: unless its phase is core, the order is not sent (market_closed, CANCELLED, reached_broker_ false), since Alpaca would queue a day order for the next session. A failed read refuses the order with the read's own category, not sent. The clock covers market-wide state (an unscheduled closure), not a single stock's halt, and a fill between a read and the order is not seen.

Alpaca's refusals seen on the paper host (422 42210000, 403 40310000) are INVALID_ARGUMENT; any other failure leaves the outcome unknown (PROTOCOL, or HTTP for 5xx, or the transport's), to be read back.
