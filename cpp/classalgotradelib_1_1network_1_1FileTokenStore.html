Detailed Description

A TokenStore in a private folder: one token file and one lock file per identity. POSIX only; not provided on Windows.

The folder is created (mode 0700) if it does not exist; its parent must. For identity ID the store keeps ID.token (JSON: the token and its expiry in nanoseconds since the epoch, replaced by writing ID.tmp, flushing it and renaming it) and ID.lock (an flock lock, never removed). The folder and every file must be owned by the user running the program and give no permission to group or others; a store that finds otherwise refuses and leaves the file as it was. A symbolic link at the folder's path or at a file's is not followed. Descriptors are closed on exec. A token file that is not well formed reads as no token.

Keep the folder on a local disk: flock over a network file system is unreliable. A lock held when the process forks without exec is held by the child too, until the child closes the descriptor or exits. The token is a bearer credential; the folder is as sensitive as the app secret.
